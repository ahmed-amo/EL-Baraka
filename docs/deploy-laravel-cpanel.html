Deploy Laravel from a private GitHub repository to cPanel

Deploy your Laravel application to the main domain elbarakaconseil.dz using the existing cPanel account elbarakaconseil. Application code stays outside the public web directory so .env and source files are not directly exposed.

GitHubPrivate repository — source code and version history
cPanelGit Version Control — clone and update securely
Laravel appStored outside public_html, with PHP and Composer
Domainelbarakaconseil.dz serves Laravel’s public files and routes

This uses cPanel’s Git deployment functionality, with SSH authentication for your private repository.

Before you start

Hosting must support PHP, Composer, SSH, and your application’s database. Some shared hosts restrict these features. Confirm Terminal, PHP, Git, and Composer work before continuing.

Step 1 — Check your cPanel hosting

  1. Click Search Tools at the top right.
  2. Search for Terminal and open it.
  3. Run these commands one at a time:
whoami
php -v
git --version
composer --version

Expected results

  • whoami returns elbarakaconseil.
  • PHP shows a version supported by your Laravel application.
  • Git and Composer display their versions.

If Terminal is missing, or PHP, Git, or Composer isn’t available, contact your hosting provider. Also search cPanel for Select PHP Version or MultiPHP Manager and confirm the main domain uses a PHP version supported by your project’s composer.json.

Step 2 — Back up your existing website

  1. Open Files → File Manager.
  2. Open public_html.
  3. If it contains an existing website, select its files and create a backup archive, or download a copy.
  4. Do not delete or overwrite the existing website yet.

Your main domain will normally use:

/home/elbarakaconseil/public_html/

Verify the domain’s actual document root before deploying.

Step 3 — Give cPanel access to your private GitHub repository

Because the repository is private, cPanel needs an SSH key authorized by GitHub.

3.1 Generate an SSH key

mkdir -p ~/.ssh
chmod 700 ~/.ssh

ssh-keygen -t ed25519 \
  -C "cpanel-laravel-deploy" \
  -f ~/.ssh/github_laravel

When prompted for a passphrase, you can leave it empty by pressing Enter twice if your host permits it.

chmod 600 ~/.ssh/github_laravel
chmod 644 ~/.ssh/github_laravel.pub

3.2 Copy your public key

cat ~/.ssh/github_laravel.pub
Copy the entire public key output. Never share the private key file ~/.ssh/github_laravel.

3.3 Add the key to GitHub

  1. Open your private repository on GitHub.
  2. Go to Settings → Deploy keys.
  3. Click Add deploy key.
  4. Title it cPanel Laravel Production.
  5. Paste the public key.
  6. Leave Allow write access unchecked.
  7. Click Add key.

Read-only access is enough for cPanel to clone and pull.

3.4 Test the connection

ssh -i ~/.ssh/github_laravel \
  -o IdentitiesOnly=yes \
  -T git@github.com

If prompted to confirm GitHub’s host authenticity, verify its fingerprint against GitHub’s documentation before accepting. A successful connection typically identifies your GitHub username and notes that shell access is unavailable — that is normal. If you get Permission denied (publickey), check the deploy key and private key permissions.

Step 4 — Clone your repository into cPanel

  1. Search for Git Version Control.
  2. Click Create.
  3. Enable Clone a Repository if shown.
  4. Fill in the fields below, then click Create.

Clone URL (replace OWNER and REPOSITORY):

git@github.com:OWNER/REPOSITORY.git

Repository Path

/home/elbarakaconseil/repositories/laravel-app

Repository Name

laravel-app
The repository directory must stay separate from public_html. Do not clone the full Laravel application into the public web directory.

Step 5 — Install Laravel dependencies

cd /home/elbarakaconseil/repositories/laravel-app
ls -la
composer install --no-dev --optimize-autoloader

You should see artisan, composer.json, app, bootstrap, and public. If the app has frontend assets, build them where Node.js is available and deploy the generated assets. Enable any missing PHP extensions in cPanel if Composer reports them.

Step 6 — Create your production database

  1. Search for MySQL Database Wizard or Manage My Databases.
  2. Create a database, for example elbarakaconseil_app.
  3. Create a database user with a strong unique password.
  4. Grant that user privileges on the new database.
  5. Save the database name, username, password, and host.

cPanel often prefixes names with the account username — use the exact names shown in the interface.

If the app uses PostgreSQL, you need PostgreSQL support from the host.

Step 7 — Configure your production .env

cd /home/elbarakaconseil/repositories/laravel-app
cp .env.example .env
If .env already exists, do not overwrite it.

Set production values such as:

APP_ENV=production
APP_DEBUG=false
APP_URL=https://elbarakaconseil.dz

DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=YOUR_CPANEL_DATABASE_NAME
DB_USERNAME=YOUR_CPANEL_DATABASE_USER
DB_PASSWORD="YOUR_STRONG_DATABASE_PASSWORD"

Also configure mail, cache, session, storage, payments, and API keys as needed.

php artisan key:generate

Generate a key only for a fresh install. Preserve an existing production APP_KEY. Never commit .env to GitHub or expose it through public_html.

Step 8 — Point the main domain to Laravel’s public files

Laravel must serve requests through public/index.php, not the whole project directory.

  • Preferred: Point the main domain document root to /home/elbarakaconseil/repositories/laravel-app/public.
  • Fallback: If the domain must use public_html, copy Laravel’s public files there and fix entry-point paths.

8.1 Copy the public files (fallback)

cp -a \
  /home/elbarakaconseil/repositories/laravel-app/public/. \
  /home/elbarakaconseil/public_html/

8.2 Fix index.php

Open /home/elbarakaconseil/public_html/index.php and change paths similar to:

require __DIR__.'/../repositories/laravel-app/vendor/autoload.php';

$app = require_once __DIR__.'/../repositories/laravel-app/bootstrap/app.php';

If present, also update maintenance path to:

__DIR__.'/../repositories/laravel-app/storage/framework/maintenance.php'

Keep the rest of Laravel’s original index.php intact and check every relative path.

Step 9 — Finish the Laravel setup

cd /home/elbarakaconseil/repositories/laravel-app
php artisan optimize:clear
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

Run migrations only after confirming they are intended for this production database. Set storage permissions and the public storage link if needed. With the fallback deploy, ensure public_html/storage serves uploaded files correctly.

Step 10 — Test the live domain

Open https://elbarakaconseil.dz and test the homepage, login, database operations, uploads, and API routes.

If something fails, check:

  • storage/logs/laravel.log
  • cPanel Errors page
  • PHP version and extensions
  • .env database settings
  • File and directory permissions
  • SSL certificate
Keep APP_DEBUG=false in production. Do not expose the whole Laravel project or .env publicly.

Step 11 — Update after GitHub pushes

Pushing to GitHub does not automatically update the live site. Pull and deploy manually:

  1. Open Git Version Control.
  2. Find laravel-app → Manage.
  3. Open Pull or Deploy.
  4. Click Update from Remote.
  5. Click Deploy HEAD Commit if a .cpanel.yml file is configured.
  6. Run Composer, migration, and cache commands in Terminal as needed.
  7. Update public_html with any changed public assets.

For repeatable deployment, configure a .cpanel.yml file to copy public assets and automate tasks. Do not copy the entire Laravel repository into public_html.
